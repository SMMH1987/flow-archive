# ارتباط پروژه‌ها با هم — استاندارد، پروتکل، زیرساخت (دستورالعمل v0)

تاریخ: ۲۰۲۶-۱۱-۰۷ · وضعیت: **از دانش مدل، بدون جست‌وجوی وب** ← نسخهٔ پروتکل‌ها را قبل از پیاده‌سازی با مستند رسمی چک کن.

## مسئله
چند پروژهٔ مستقل (آوانگار/همدبیر، حق‌پرس، بات‌ها، …) باید بتوانند از هم کار بخواهند، بی‌آنکه هر جفت یک اتصال دستی جدا داشته باشند.

## معماری پیشنهادی — ۴ لایه، از ساده به پیچیده
| لایه | چه | استاندارد | چه وقت |
|---|---|---|---|
| ۱ دفتر ظرفیت | فایل `capabilities.yaml`: کار ← پروژه ← آدرس ← احراز هویت | خودساخته (YAML) | **همین حالا** |
| ۲ قرارداد API | هر پروژه یک `openapi.yaml` | OpenAPI 3.x | **همین حالا** (آوانگار تقریباً دارد: `API-GUIDE.md`) |
| ۳ اتصال به Claude/ایجنت | روی هر پروژه یک پوستهٔ نازک MCP که همان API را «ابزار» می‌کند | MCP (Streamable HTTP) | وقتی Claude/ایجنت باید مستقیم صدا بزند |
| ۴ ایجنت با ایجنت | کارت معرفی ایجنت + وظیفهٔ طولانی + استریم | A2A (Agent2Agent) | فقط برای ایجنت‌های واقعاً گفت‌وگومحور مثل حق‌پرس؛ اگر یک endpoint ساده کافی است لازم نیست |

زیرساخت مشترک (کم‌هزینه):
- **احراز هویت:** هر پروژه کلید جدا و محدود به کار (مثل `avn_live_…` آوانگار)؛ کلیدها فقط در `.env`، در `capabilities.yaml` فقط نام متغیر.
- **کار ناهم‌زمان:** webhook با امضای HMAC (آوانگار الان `whsec_` دارد) — همان الگو را برای بقیه کپی کن.
- **رویداد بین پروژه‌ها (بعداً):** اگر ارتباط زیاد شد، یک صف (Redis Streams یا NATS)؛ قبل از آن نه.
- **ثبت خطا و ردیابی:** هر درخواست یک `request_id` که از پروژه‌ای به پروژهٔ بعد منتقل شود.

## نمونهٔ capabilities.yaml (پیشنهاد؛ مقدار حق‌پرس را خودت پر کن)
```yaml
- task: speech_to_text
  project: avanegar-hamdabir
  base_url: https://api.hamdabir.co-ir.com:8440
  auth: {type: api_key, env: AVANEGAR_API_KEY}   # نام متغیر، نه مقدار
  async: {callback: webhook, signature: HMAC whsec_}
  contract: docs/API-GUIDE.md
- task: legal_qa_and_contract_drafting
  project: hagh-pors-lawyer-agent
  base_url: UNKNOWN            # ask: آدرس؟ HTTP ساده یا ایجنت گفت‌وگومحور؟
  auth: UNKNOWN
  needs_human_gate: true       # امضا/ورود به قرارداد فقط با تأیید انسان
```

## ترتیب اجرا (هر قدم نتیجهٔ دیدنی دارد)
1. `capabilities.yaml` را با ۲ پروژه (آوانگار + حق‌پرس) بساز ← مسیریاب در فلو از همین می‌خواند.
2. برای حق‌پرس بپرس/ثبت کن: آدرس، نوع (REST ساده؟ ایجنت؟)، احراز هویت ← جای UNKNOWN پر می‌شود.
3. اگر حق‌پرس REST است ← `openapi.yaml` بنویس؛ اگر ایجنت گفت‌وگومحور است ← A2A را بررسی کن.
4. فقط وقتی لازم شد: پوستهٔ MCP روی هر پروژه.

## ⚠️ تله‌ها
- پروتکل را زود انتخاب نکن؛ لایهٔ ۱ و ۲ بدون پروتکل جدید همین حالا کار می‌کند.
- A2A و MCP جای هم نیستند: MCP = ابزار صدا زدن؛ A2A = ایجنت با ایجنت.
- هر ارجاع حقوقی که اثر قراردادی دارد باید gate انسانی بماند (در فلو `gateStep` است).
