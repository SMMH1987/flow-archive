# دستورالعمل ساخت هر فرایند / ایجنت (مدل Camunda)
وضعیت: تثبیت‌شده به درخواست Siax، 2026-11-13. نمونهٔ مرجع: `agents/hr-recruit/`.
الگو گرفته از Camunda (BPMN + DMN): فلو ثابت، قانون انتخاب جدا، زیرفلو برای بخش بزرگ.

## ساختار هر ایجنت
```
agents/<name>/
  flow.c4             فلو اصلی: فقط گام‌های مشترک + نقطه‌های decision (یک خانه برای هر گام)
  rules.yaml          جدول‌های تصمیم (DMN): FIRST یا COLLECT
  subflows/*.c4       بخشی که بیش از ۳ گام متفاوت دارد
  questionnaire.yaml  پرسشنامهٔ سازمان؛ هر پاسخ = org.<id>
  orgs/<org>.yaml     پاسخ‌های هر سازمان (یک بار پر می‌شود)
  profiles/*.yaml     هر موقعیت/فرد: فقط چند فیلد ورودی
  plan.py             اجرای خشک: سازمان + پروفایل → گام‌های اجرا و ردشده با دلیل
```

## سه لایهٔ ورودی
1. **سازمان** (پرسشنامه): چه گزینه‌هایی برای این سازمان انجام شود یا رد شود.
2. **پروفایل** (موقعیت/فرد): کارآموز، متخصص سئو، ...
3. **اجرا**: دادهٔ هر اجرا جدا ذخیره می‌شود؛ تعریف کپی نمی‌شود.

## قواعد
- هیچ فلو یا گامی برای یک سازمان/پروفایل کپی نمی‌شود (SSOT)؛ تفاوت فقط در rules.yaml.
- هر گام `external: yes|no` دارد؛ external = gate (پول، حقوقی، انتشار) و منتظر انسان می‌ماند (`needs_input`).
- تفاوت کم → ردیف جدول؛ بیش از ۳ گام متفاوت → زیرفلو.
- ترتیب: جدول‌ها در جای درست فلو (مثلاً پیش/پس از مصاحبه)، نه همه در یک جا.
- هر ردشده با دلیل گزارش شود.

## مراحل ساخت فرایند جدید
1. طرح کلی و نقش‌ها (طبق دستور پروژه).
2. گام‌های مشترک → flow.c4؛ برای هر گام بهترین skill.
3. تفاوت‌ها → rules.yaml؛ بخش‌های بزرگ → subflows.
4. سؤال‌های سازمان → questionnaire.yaml.
5. ۲–۳ پروفایل و ۲ سازمان نمونه؛ `python plan.py orgs/x.yaml profiles/y.yaml` برای هر ترکیب.
6. بازبینی Siax، بعد اتصال به n8n / MCP.
