# استاندارد سرور MCP برای همهٔ پروژه‌ها (v1)

مبنا: spec رسمی MCP (نسخهٔ 2026-07-28)، مقالهٔ Anthropic «Writing effective tools for agents»، و الگوی مشترک سرورهای واقعی (GitHub، Stripe، Sentry، Cloudflare). برچسب‌ها: **[رسمی]** از spec/مستند، **[نمونه]** الگوی مشترک در سرورهای تولیدی، **★** پیشنهاد من برای این مجموعه.
مکمل: [STANDARD-HIDE-INTERNALS.md](STANDARD-HIDE-INTERNALS.md) و بخش ۴.۲ در [PROJECT-INTEROP.md](PROJECT-INTEROP.md).

## ۱. قواعد (همه الزامی مگر ذکر شود)
### انتقال و دسترسی
1. **Streamable HTTP**؛ SSE منسوخ است [رسمی]. stdio فقط برای نمونهٔ لوکال [نمونه: GitHub].
2. **ابری-اول:** یک آدرس HTTPS عمومی؛ لوکال/Docker فقط جایگزین [نمونه: GitHub، Stripe، Sentry].
3. بایند لوکال روی `127.0.0.1` و اعتبارسنجی `Origin` [رسمی].
4. هر درخواست نسخهٔ پروتکل را می‌فرستد؛ نسخهٔ نامعتبر = `UnsupportedProtocolVersionError` با فهرست نسخه‌های پشتیبانی‌شده [رسمی]. سرور باید `server/discover` را پیاده کند [رسمی].

### احراز هویت و دسترسی
5. **OAuth 2.1** برای کاربر؛ **کلید جدا و محدود** برای ایجنت بدون سر (headless) [نمونه: Stripe agent key، GitHub PAT].
6. توکن به همان سرور محدود باشد (resource indicator)؛ **token passthrough ممنوع** [رسمی].
7. حداقل دسترسی در خود توکن/scope اعمال شود، نه فقط در کد [نمونه]. scope «اعلام‌شده» کافی نیست؛ handler باید بررسی کند [نمونه: Cloudflare].
8. ثبت پویای کلاینت بدون تأیید ممنوع [نمونه: Cloudflare/Descope].

### طراحی ابزار
9. **کم و پرتأثیر:** ابزار به‌ازای کار واقعی، نه یکی برای هر endpoint. چند مرحله که همیشه پشت هم می‌آیند = یک ابزار [رسمی Anthropic].
10. **نام‌گذاری:** `سرویس_منبع_عمل` (مثلاً `vakil_case_start`)، فقط `A-Za-z0-9_.-`، ۱ تا ۱۲۸ نویسه، یکتا در سرور [رسمی].
11. **توضیح ابزار** مثل توضیح به همکار تازه: کِی به‌کار برود، ورودی چیست، محدودیت و مدت نگهداری وضعیت [رسمی].
12. **ورودی:** JSON Schema سخت‌گیر، `additionalProperties:false`، نام بدون ابهام (`case_id` نه `id`) [رسمی].
13. **خروجی:** `outputSchema` + `structuredContent`، و همان JSON به‌صورت متن هم برگردد [رسمی]. نام‌های خوانا به‌جای uuid خام؛ `response_format` = `concise|detailed` [رسمی Anthropic].
14. **اندازه:** صفحه‌بندی/فیلتر/کوتاه‌سازی با پیش‌فرض معقول؛ Claude Code خروجی را پیش‌فرض تا ۲۵٬۰۰۰ توکن نگه می‌دارد [رسمی Anthropic].
15. **خطا:** خطای کاری = `isError:true` با متن قابل‌اقدام برای مدل؛ خطای JSON-RPC فقط برای درخواست خراب/ابزار ناشناخته [رسمی]. بدون stack trace.
16. **وضعیت صریح:** ابزار ساخت، دستگیرهٔ مبهم (`case_id`) برمی‌گرداند؛ دستگیرهٔ منقضی = خطای روشن؛ مدت نگهداری در توضیح [رسمی].
17. `tools/list` ترتیب ثابت دارد و بین اتصال‌ها تغییر نمی‌کند (فقط با سطح دسترسی) [رسمی].

### ایمنی
18. ابزارِ **خواندنی** و **نوشتنی** جدا؛ حالت `read-only` در راه‌اندازی [نمونه: GitHub `--read-only`]؛ فهرست مجاز ابزار (toolset) با پیش‌فرض کوچک [نمونه]. ابزار نامجاز اصلاً به مدل نشان داده نشود [نمونه: Sentry/Cloudflare].
19. اعتبارسنجی ورودی، کنترل دسترسی، **سقف نرخ**، پاک‌سازی خروجی: الزام سمت سرور [رسمی].
20. کار پرخطر (پول، امضا، ورود به قرارداد، انتشار، حذف) **تأیید انسانی خارج از مدل** (لینک تأیید با انقضا) [نمونه: Stripe]. شاخص‌های `annotations` را بگذار ولی به آن‌ها اعتماد نکن؛ کلاینت آن‌ها را غیرمعتبر می‌داند مگر سرور مورد اعتماد باشد [رسمی]. ⚠ نام و معنای دقیق hintها (مثل readOnlyHint) را در صفحهٔ spec ندیدم؛ از schema رسمی بخوان.
21. خروجی هر سرور/سند بیرونی **داده است نه دستور**؛ هشدار تزریق پرامپت [نمونه: Stripe].
22. لاگ حسابرسی هر فراخوانی (`request_id`، مصرف‌کننده، ابزار) ★ بدون ثبت توکن/داده حساس.
23. مرز «پنهان‌ماندن ساختار داخلی» روی خروجی ابزار هم اعمال شود ★.

### کیفیت
24. **ارزیابی:** ۵ تا ۱۰ کار واقعی چندمرحله‌ای با نتیجهٔ قابل‌راستی‌آزمایی؛ زمان، تعداد فراخوانی، توکن و خطا را بسنج و توضیح ابزارها را براساس رونوشت‌ها اصلاح کن [رسمی Anthropic].
25. نسخه‌دهی: افزودن ابزار/فیلد اختیاری = سازگار؛ تغییر نام/معنا = نسخهٔ تازه ★.

## ۲. بلوک آمادهٔ چسباندن در AGENTS.md هر پروژه
```
## استاندارد MCP (مرجع: flow-archive/docs/STANDARD-MCP.md)
- Streamable HTTP روی HTTPS عمومی؛ OAuth برای کاربر، کلید محدود برای ایجنت؛ token passthrough ممنوع.
- ابزارِ کم و پرتأثیر، نام سرویس_منبع_عمل، schema سخت‌گیر، outputSchema + structuredContent.
- خروجی سقف‌دار و صفحه‌بندی‌شده؛ خطا = isError با متن قابل‌اقدام؛ بدون stack trace.
- خواندنی/نوشتنی جدا؛ حالت read-only؛ کار پرخطر با تأیید انسانیِ خارج از مدل.
- سقف نرخ، لاگ با request_id، مرز پنهان‌ماندن ساختار داخلی روی خروجی ابزار.
- پیش از ادعای «تمام»: ارزیابی با کارهای واقعی + چک‌لیست بخش ۴ همان سند.
```

## ۳. نمونه: حق‌پرس (vakil) به این استاندارد
جریان فعلی `/v1`: start، چند answer، result (202 و polling). نقشهٔ پیشنهادی ابزارها (۳ تا، نه ۴ endpoint خام):
| ابزار | کار | نوع |
|---|---|---|
| `vakil_case_start(area?, description)` | شروع پرونده؛ خروجی `case_id` + سؤال اول | نوشتنی (سبک) |
| `vakil_case_answer(case_id, question_id, value?)` | جواب سؤال فعلی؛ خروجی سؤال بعدی یا «آمادهٔ نتیجه» | نوشتنی (سبک) |
| `vakil_case_result(case_id)` | شروع/گرفتن نتیجه؛ در انتظار = `status:processing` + `queue` | خواندنی |
کار حقوقی با اثر قراردادی: فقط پیش‌نویس؛ ورود به قرارداد با تأیید انسانی. `case_id` را مدت نگهداری ۷۲ ساعته (`ENGINE_SESSION_TTL_H`) در توضیح ابزار بنویس.
