## ۱. BPMN چیست (منبع)
- BPMN 2.0.2 از OMG (۲۰۱۴)، همان استاندارد ISO/IEC 19510:2013. منبع: https://www.omg.org/spec/BPMN/2.0.2/
- قواعد سبک: کتاب «BPMN Method and Style» نوشتهٔ Bruce Silver (سطح ۱ توصیفی، سطح ۲ تحلیلی، سطح ۳ اجرایی).
- DMN 1.x از OMG برای جدول تصمیم. ما همین را در `rules.yaml` داریم (FIRST / COLLECT).
- نمونهٔ موفق: Camunda (BPMN + DMN اجرایی). مدل ساخت ما در ۱۳ نوامبر هم از روی همین گرفته شد.

## ۲. نگاشت BPMN به ساختار ما
| عنصر BPMN | معنی | در فایل‌های ما |
|---|---|---|
| Pool (استخر) | یک سازمان یا طرف بیرونی | سازمان = `org`؛ طرف بیرونی (مشتری، بانک، سامانهٔ مؤدیان) = استخر جدا |
| Lane (خط) | نقش انجام‌دهنده | **دپارتمان** (div) و در سطح پایین‌تر **ایجنت** (`org-agents.yaml`) |
| User Task | کار با تأیید انسان | `mode: gate` (پول، حقوقی، انتشار بیرونی، حذف) |
| Manual / ask | پرسش از انسان | `mode: ask` |
| Service Task | کار خودکار ایجنت | `mode: auto` |
| Business Rule Task | تصمیم با جدول | ردیف در `rules.yaml` (DMN) |
| Send / Receive Task | پیام به بیرون یا از بیرون | `external: yes` و حتماً gate |
| Exclusive Gateway (X) | فقط یک مسیر | `rules.yaml` با hit: FIRST |
| Inclusive Gateway (O) | چند مسیر ممکن | `rules.yaml` با hit: COLLECT |
| Parallel Gateway (+) | هم‌زمان | چند قدم بدون ترتیب (n8n: شاخهٔ موازی) |
| Event-based Gateway | هرکدام زودتر رسید | انتظار پاسخ بیرونی (مثلاً پرداخت یا لغو) |
| Start Event (رویداد شروع) | محرک | `trigger` در کاتالوگ: دستی، زمان‌دار، پیام |
| Timer Event | زمان یا مهلت | مهلت قانونی (مثلاً لیست بیمه تا آخر ماه بعد) |
| Error / Escalation Event | خطا و ارجاع به بالا | ارجاع به سرپرست (`reportsTo`) |
| Compensation | برگرداندن کار | بازپرداخت، لغو سفارش |
| End Event | نتیجهٔ پایانی | `end` در کاتالوگ؛ هر مسیر یک پایان با نام نتیجه |
| Sub-Process / Call Activity | زیرفلو | `subflows/*.c4` (بیش از ۳ قدم متفاوت) |
| Message Flow (خط‌چین) | تحویل بین دپارتمان یا سازمان | `inputs/outputs` ایجنت (خط‌های چارت) |
| Data Object / Store | سند و داده | دادهٔ اجرا (لایهٔ سوم)، جدا از تعریف |

## ۳. قواعد نگارش (style) — هرکدام قابل بررسی خودکار
1. نام هر Task = فعل + مفعول («صدور صورتحساب»، نه «صورتحساب»).
2. نام هر End Event = نتیجه («سفارش ارسال شد»)، و هر مسیر به یک End می‌رسد.
3. هر Gateway تصمیم سؤال دارد و هر خروجی برچسب جواب دارد.
4. هر Task دقیقاً یک Lane دارد، یعنی یک ایجنت یا دپارتمان مسئول. ایجنت بی‌صاحب خطاست.
5. قدم بیرونی (`external: yes`) بدون gate انسانی خطاست. این قانون STANDARD-RULES است.
6. حداکثر حدود ۱۰ قدم در هر سطح؛ بیشتر از آن به Sub-Process می‌رود.
7. سطح ۱ (برای Siax): فقط قدم‌ها و نقش‌ها. سطح ۲: + رویدادها، خطا و مهلت. سطح ۳: + داده و اتصال n8n/MCP.
8. یک تعریف برای هر ورک‌فلو. تفاوت سازمان یا کشور (مثلاً ایران) با `rules.yaml` و تگ `#loc_ir`، نه کپی.
9. هر ورک‌فلو کد APQC دارد (مثلاً 8.2 حساب‌های پرداختنی) تا با استاندارد جهانی مقایسه‌پذیر باشد.
10. هر ورک‌فلو مالک دارد (سرپرست یک دپارتمان) و KPI پایانی دارد.
