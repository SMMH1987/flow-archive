# چک‌لیست یک‌صفحه‌ای: برای هر سرویس کدام روش اتصال؟

برای هر سرویس/پروژهٔ تازه، یک بار پر شود و نتیجه در `capabilities.yaml` (فیلد `protocol`) ثبت شود.
وضعیت: پیشنهاد (جمع‌بندی یافته‌های `PROJECT-INTEROP.md`)؛ خودِ درخت تصمیم برداشت من است، نه استاندارد رسمی.

## گام ۱ — چهار پرسش (۵ دقیقه)
| # | پرسش | پاسخ |
|---|---|---|
| ۱ | چه کسی صدایش می‌زند؟ | برنامهٔ خودم / Claude یا Grok یا Claude Code / ایجنت دیگر |
| ۲ | کجا اجرا می‌شود؟ | لوکال / سرور با آدرس عمومی |
| ۳ | شکل کار؟ | یک سؤال-یک جواب / چندمرحله‌ای / طولانی (polling) / گفت‌وگوی دوطرفه |
| ۴ | پرخطر است؟ (پول، قرارداد، امضا، انتشار، حذف) | بله / خیر |

## گام ۲ — انتخاب
- [ ] **همیشه:** REST + OpenAPI (سطح ۱) با استاندارد `STANDARD-HIDE-INTERNALS.md`.
- [ ] پاسخ ۱ = Claude/Grok/Claude Code **و** نیاز به صدا زدن خودکار ← **MCP** (`STANDARD-MCP.md`).
  - لوکال و فقط Claude Code ← MCP روی `127.0.0.1` یا stdio کافی است.
  - claude.ai / Claude API / Grok ← آدرس HTTPS عمومی الزامی است.
- [ ] پاسخ ۱ = ایجنت دیگر **و** پاسخ ۳ = گفت‌وگوی دوطرفه یا کار طولانی ← **A2A 1.0** (کارت ایجنت) کنار MCP.
- [ ] پاسخ ۱ = فقط برنامهٔ خودم ← همان REST کافی است؛ MCP اضافه نکن.
- [ ] مدل‌های دیگر از راه OpenRouter ← REST؛ برنامهٔ مصرف‌کننده ابزار را خودش اجرا می‌کند (OpenRouter به MCP وصل نمی‌شود).

## گام ۳ — پرخطر؟
- [ ] پاسخ ۴ = بله ← `needs_human_gate: true`؛ ابزار فقط پیش‌نویس می‌دهد؛ تأیید انسانی خارج از مدل؛ ابزار نوشتنی جدا از خواندنی.

## گام ۴ — ثبت و آزمون
- [ ] ردیف `capabilities.yaml` پر شد (`protocol: rest|mcp|a2a`، آدرس، نام متغیر کلید).
- [ ] مغز سرویس از لایهٔ MCP/A2A جدا است (تغییر روش بعداً ارزان بماند).
- [ ] چک‌لیست پذیرش `STANDARD-MCP.md` §۴ و `STANDARD-HIDE-INTERNALS.md` §۴ سبز است.
