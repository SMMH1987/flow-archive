# چک‌لیست یک‌صفحه‌ای: برای هر سرویس کدام روش اتصال؟

برای هر سرویس/پروژهٔ تازه، یک بار پر شود و نتیجه در `capabilities.yaml` (فیلد `protocol`) ثبت شود.
وضعیت: پیشنهاد (جمع‌بندی یافته‌های `PROJECT-INTEROP.md`)؛ خودِ درخت تصمیم برداشت من است، نه استاندارد رسمی.

## پیش‌فرض ثابت (دیگر پرسیده نمی‌شود)
هر سرویس باید همیشه با دو خانواده مصرف‌کننده سازگار باشد:
1. **سازگار با Claude:** سرور MCP روی Streamable HTTP (Claude Code، claude.ai، Claude API).
2. **سازگار با OpenAI:** REST با OpenAPI و تعریف ابزار به قالب OpenAI (`{"type":"function","function":{name, description, parameters}}`)؛ همین قالب را مدل‌های دیگر و OpenRouter می‌فهمند و برنامهٔ مصرف‌کننده ابزار را خودش اجرا می‌کند.

یک بار تعریف، دو خروجی: schema هر ابزار را یک جا (JSON Schema) بنویس و از آن هم `inputSchema` برای MCP و هم `parameters` برای قالب OpenAI و هم OpenAPI را بساز. مغز سرویس از این لایه‌ها جدا بماند.

## گام ۱ — فقط دو پرسش (۲ دقیقه)
| # | پرسش | پاسخ |
|---|---|---|
| ۱ | کجا اجرا می‌شود؟ | لوکال (فقط Claude Code و برنامه‌های همان ماشین) / سرور با آدرس عمومی HTTPS (لازم برای claude.ai، Claude API، Grok و بات‌های ابری) |
| ۲ | شکل کار؟ | یک سؤال-یک جواب / چندمرحله‌ای / طولانی (202 و polling) |
| ۳ | پرخطر است؟ (پول، قرارداد، امضا، انتشار، حذف) | بله / خیر |

## گام ۲ — ساخت (همیشه)
- [ ] REST + OpenAPI با `STANDARD-HIDE-INTERNALS.md` (سطح ۱).
- [ ] تعریف ابزارها یک جا؛ خروجی OpenAI-قالب و MCP از همان.
- [ ] سرور MCP با `STANDARD-MCP.md`.
- [ ] لوکال: MCP روی `127.0.0.1` یا stdio؛ ابری: HTTPS عمومی + احراز هویت.
- [ ] مدل‌های دیگر از راه OpenRouter: REST/قالب OpenAI کافی است (OpenRouter خودش به MCP وصل نمی‌شود).
- [ ] **A2A 1.0 فقط اختیاری:** وقتی طرف مقابل ایجنتی است که گفت‌وگوی دوطرفه یا کار بسیار طولانی لازم دارد.
