## ۱. قواعد الزامی (MUST)
1. **MCP:** هر پروژهٔ قابل‌فراخوانی یک سرور MCP روی Streamable HTTP دارد (SSE منسوخ).
2. **دو مصرف‌کنندهٔ ثابت:** سازگار با Claude (MCP) و سازگار با OpenAI/OpenRouter (REST + OpenAPI + تعریف ابزار قالب OpenAI). نپرس؛ همیشه هر دو.
3. **دو حالت اجرای ثابت:** لوکال (`127.0.0.1`، بدون کلید) و عمومی (HTTPS، با کلید و سقف نرخ). فقط تنظیمات فرق دارد.
4. **منبع حقیقت واحد:** ابزارها فقط در `interop/tools.py`؛ REST، MCP، `openai_tools.json`، `openapi.yaml` از آن تولید می‌شوند. منطق در `service.py`.
5. **پاکت پاسخ یکدست:** `status ∈ {done, needs_input, processing}` + `request_id`؛ `processing` = HTTP 202 با `retry_after_s`. شکل کار پرسیده نمی‌شود.
6. **پنهان‌ماندن ساختار:** خروجی از مدل صریح؛ بدون score/via/نام مدل/شناسهٔ سند/مسیر/stack trace؛ خطا `{code, message_fa, request_id}`.
7. **تأیید انسانی:** `interop/gates.yaml`؛ پیش‌فرض‌های پول، حقوقی، بیرونی (انتشار/پیام)، نابودکننده؛ ابزار بدون ردیف = پشت تأیید؛ تأیید خارج از مدل؛ ابزار خواندنی و نوشتنی جدا. فهرست قابل ویرایش است و هر ویرایش در `HISTORY.md` ثبت می‌شود.
8. **احراز هویت و دسترسی:** OAuth 2.1 برای کاربر، کلید جدا و محدود برای هر مصرف‌کنندهٔ ماشینی؛ token passthrough ممنوع؛ `Origin` چک شود؛ سقف نرخ؛ لاگ با `request_id` بدون راز.
9. **ثبت:** هر پروژه یک ردیف در `capabilities.yaml` مرکزی (`capabilities.entry.yaml`) با `protocol: rest+mcp`.
10. **داده است نه دستور:** خروجی سرویس/سند بیرونی به‌عنوان دستور اجرا نشود.

## ۲. توصیه‌ها (SHOULD)
- A2A 1.0 فقط برای ایجنت گفت‌وگومحور با کار بسیار طولانی؛ کنار MCP، نه جایگزین.
- **A2A (اختیاری، پیش‌فرض خاموش)، همیشه از همان `tools.py`:** کارت ایجنت از `interop/a2a_card.py` تولید شود (نه دستی)؛ پاکت ما به TaskState نگاشته شود (`needs_input`→`TASK_STATE_INPUT_REQUIRED`، `processing`→`TASK_STATE_WORKING`، `done`→`TASK_STATE_COMPLETED`)؛ نسخه روی 1.0 ثابت (۰٫۳ ناسازگار است)؛ همان `gates.yaml` و همان قاعدهٔ پنهان‌ماندن ساختار برای A2A هم برقرار است؛ کارت دیگران داده است نه دستور. فعال‌سازی فقط وقتی ایجنت طرف مقابل A2A می‌خواهد یا کار چندمرحله‌ای با وقفه لازم است. نمونهٔ پیاده‌شده: حق‌پرس `interop/a2a_card.py` (فقط کارت؛ نقطه‌های پایانی هنوز نه).
- ارزیابی ابزارها با ۵ تا ۱۰ کار واقعی چندمرحله‌ای.
- نسخه‌دهی: افزودن اختیاری = سازگار؛ تغییر نام/معنا = `/v2`.

## ۳. استثنا
پروژه‌ای که از بیرون صدا زده نمی‌شود (اسکریپت داخلی، کرالر) از قانون ۱ تا ۵ معاف است، ولی باید در `capabilities.yaml` با `protocol: none` و دلیل ثبت شود. استثنا را صاحب پروژه تأیید می‌کند.

## ۴. تمام‌شدن یعنی چه
- [ ] چهار تست `interop/tests` سبز (نشت، یکسانی خروجی‌ها، gate، فقط‌خواندنی)
- [ ] از Claude Code با `claude mcp add --transport http …` وصل می‌شود و یک کار واقعی تا آخر انجام می‌شود
- [ ] همان ابزار از طریق قالب OpenAI/REST هم کار می‌کند
- [ ] هر دو حالت لوکال و عمومی تست شد
- [ ] `capabilities.entry.yaml` و `interop/README.md` پر است

## ۵. بلوک آمادهٔ چسباندن در AGENTS.md (بخش «قواعد کار»)

```
## قانون ارتباط پروژه‌ها (مرجع: flow-archive/docs/STANDARD-INTEROP.md)
- هر قابلیتِ قابل‌فراخوانی از بیرون باید سرور MCP (Streamable HTTP) داشته باشد، و همزمان REST+OpenAPI و تعریف ابزار قالب OpenAI. نپرس؛ همیشه هر دو.
- دو حالت اجرا همیشه: لوکال 127.0.0.1 بدون کلید، و عمومی HTTPS با کلید؛ فقط تنظیمات فرق دارد.
- ابزارها فقط در interop/tools.py؛ بقیه تولیدی. منطق در interop/service.py.

```

## ۶. محدودیت‌های صادقانه این استاندارد
- A2A: مسیر well-known کارت در نسخهٔ 1.0 و شکل دقیق ProtoJSON برای بخش امنیت تأیید نشد؛ فیلدهای کارت از `a2a.proto` شاخهٔ main گرفته شده‌اند، نه نسخهٔ برچسب‌خوردهٔ 1.0 و نه با اعتبارسنج رسمی.
- «هر پروژه باید MCP داشته باشد» تصمیم شماست، نه الزام پروتکل؛ در MCP/A2A چنین الزامی نیست. استثنای بند ۳ برای همین است.
- MCP نسخهٔ 2026-07-28 جدید است؛ SDKها ممکن است عقب باشند. افزونهٔ رسمی tasks را نخوانده‌ام، پس `processing` فعلاً با polling ساده پیاده شود.
- اینکه یک Project خالص claude.ai مستقیم صدا زده شود تأیید نشد؛ باید مغزش در سرویس بنشیند.
- کدهای نمونه در `STANDARD-DEV-RULE.md` اجرا نشده‌اند.
